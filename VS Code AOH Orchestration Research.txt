Architectural Research Report: Agentic Orchestration Harness (AOH) for Visual Studio Code
Deliverable A: Executive Findings
The Agentic Orchestration Harness (AOH) is an enterprise-grade orchestration framework designed to execute across Visual Studio Code custom agent runtimes1. Designed for multi-tiered organizational environments—such as the Global Markets Technology (GMT) division with its Alpha and Beta teams—AOH establishes operational governance, state persistence, subagent delegation control, and telemetry capture3.
Designing a resilient orchestration harness requires navigating a fundamental architectural boundary within Visual Studio Code: the operational split between the Local Extension Host Harness and the Agent Host Harness (which executes out-of-process runtimes for GitHub Copilot, Anthropic Claude, and OpenAI Codex)2. The Local harness runs directly inside the VS Code Extension Host process, offering native lifecycle hooks (.github/hooks/*.json), agent-scoped hook commands, and synchronous tool interception1. In contrast, Agent Host sessions run on dedicated, isolated background processes5. VS Code settings controlling local hooks, such as chat.useHooks and chat.hookFilesLocations, do not configure or govern Agent Host sessions5.
Because Visual Studio Code custom agents do not natively provide persistent long-term memory APIs or cross-session state databases6, AOH introduces an explicit workspace memory architecture4. Transient session context is augmented by file-backed state stores, structured capability registries, and Model Context Protocol (MCP) state adapters4. Delegation topology is governed using explicit allow-lists (agents frontmatter property combined with the agent tool)1 and structured handoffs (handoffs frontmatter property)1. Non-invocable specialist agents (user-invocable: false) are shielded from direct user interaction while remaining fully accessible to authorized team orchestrators1.

Explanation of Directories and Ownership
1. .github/agents/ (VS Code Discovered): Discovered natively by VS Code1. Every .agent.md file in this directory is exposed in the Chat UI agent selector or registered as a callable subagent1. Subfolders within .github/agents/ are not natively parsed for agent discovery in standard VS Code configurations1.
2. .github/skills/ (VS Code Discovered): Discovered natively by VS Code8. Each subdirectory must contain a SKILL.md file whose name frontmatter property matches the directory name exactly8.
3. .github/instructions/ (VS Code Discovered): Discovered natively by VS Code9. Contains *.instructions.md files equipped with applyTo glob patterns to automatically inject instructions based on target file paths9.
4. .github/hooks/ (VS Code Discovered): Discovered natively by the VS Code Local harness5. Stores *.json configuration files that map lifecycle events to script executables5.
5. .aoh/ (AOH Framework Managed): Managed entirely by AOH runtime scripts and MCP adapters4. VS Code treats this directory as standard workspace files. It houses configuration manifests, audit logs, workflow finite state machines, and agent memory banks4.
6. scripts/ (AOH Framework Managed): Houses Python and Bash execution tools invoked by lifecycle hooks, agent skills, or MCP servers5.
Script Compatibility and Cross-Platform Portability
To guarantee seamless execution across Windows PowerShell, macOS, and Linux Git Bash environments, script invocations must adhere to strict platform standards5:
* Path Resolvers: All relative paths within agent definitions, skill files, and hook maps must use Unix-style forward slashes (/)8. VS Code internally converts forward slashes to system-native separators across all supported operating systems5.
* Platform Neutrality: Hook executables should invoke cross-platform runtimes (such as python3 or node) rather than OS-dependent shell scripts5. Where native platform shell scripts are required, platform-specific overrides must be specified using the standard windows, linux, and osx hook keys5.
* Relative Path Resolution: Paths declared in custom agents resolve relative to the agent file location1. Paths in hooks.json resolve relative to the workspace root5.

Reality of Token and Prompt Capture
The VS Code Local hook API passes tool names, parameters, and invocation outputs directly to the script via standard input (stdin)5. However, the exact assembled prompt string sent to the underlying model provider (which incorporates system wrappers and hidden context) as well as exact API token consumption counts are not fully exposed in hook payloads5.
To establish token and prompt accounting without relying on brittle transcript scraping, AOH employs a multi-tiered approach:
               1. Local Harness: Computes estimated token counts within hook-handler.py using standard tokenizer libraries applied to user prompts and tool payload text strings.
               2. Agent Host Harness: Utilizes provider-level telemetry endpoints or local API proxy wrappers to capture exact token usage and billing data5.

Deliverable F: Orchestration, Delegation, and Memory Architecture
Hierarchy and Delegation Dynamics
Orchestrating work across division and team boundaries requires strict execution limits to prevent circular calls or unauthorized cross-team actions1. AOH enforces these boundaries using explicit frontmatter directives rather than filesystem directory containment1:
               1. Subagent Delegation vs. Handoffs:
               * Subagent Delegation: Managed programmatically using the agent tool1. The calling agent retains session ownership, invokes the target agent, receives the child agent's execution summary, and proceeds with its task1. Managed via the frontmatter agents list1.
               * Handoffs: Rendered as interactive UI buttons upon task completion1. Handoffs transition primary user focus from one agent to another while transferring context1.
               2. Preventing Circular and Unbounded Delegation:
               * Setting agents: [] explicitly prohibits an agent from delegating to any subagent1. Specialist agents MUST specify agents: []1.
               * Team orchestrators may only invoke subagents explicitly listed in their agents allow-list1.
               * Self-referential delegation requires setting chat.subagents.allowInvocationsFromSubagents to true1. AOH leaves this setting disabled by default to eliminate recursive loops1.

Persistent Memory Architecture
Because VS Code custom agents lack native persistent memory across sessions6, AOH establishes a three-tier state architecture4:
               1. Transient Session Context: In-memory conversation history and active window context4. Cleared upon chat reset13.
               2. Workspace Memory Banks (File-Backed): JSON documents stored in .aoh/memory/{division|team}/. Stored facts, architecture decisions, and operational context are loaded into prompts using Markdown links or #file: references1.
               3. Dynamic Memory MCP Server: Configured in .vscode/mcp.json7. Exposes state tools (aoh_read_memory, aoh_write_memory) for semantic search and state updates across workspaces4.

Deliverable G: Security, Operational Risks, and Practical Workarounds
               1. Least Privilege Tool Allocation:
               * Planning and auditing agents must be granted read-only tools (e.g., search/codebase, read/problems) to prevent unapproved edits1.
               * Broad command tools (such as terminal/runCommand) should be reserved exclusively for team orchestrator agents1.
               2. Terminal Execution Controls:
               * Built-in VS Code terminal approvals require user confirmation prior to running shell commands8. AOH configurations must operate within these safety controls.
               3. Data Masking and Credential Protection:
               * Telemetry hooks (hook-handler.py) automatically redact high-entropy strings, API keys, JWTs, and private keys before committing trace logs to .aoh/audit/trace.jsonl.
               4. Workspace Trust and Local Hooks Security:
               * Executable hooks run with the full security permissions of the VS Code process5. Local hooks (chat.useHooks) execute only within explicitly trusted workspaces5.
Practical Architectural Workarounds
               * Harness Parity Workaround: Because Agent Host sessions do not execute local .github/hooks/*.json commands5, critical governance rules are duplicated within custom Agent Skills (SKILL.md) and MCP servers4. Skills execute across all runtimes uniformly8.
               * Cross-Session Memory Workaround: To maintain state without native memory support6, AOH uses an MCP state server defined in .vscode/mcp.json7. Agents update and query state via dedicated MCP tools4.
               * Deterministic Approval Gates: Rather than relying solely on model prompt compliance, a PreToolUse hook intercepts sensitive shell commands (e.g., database updates) and halts execution until user confirmation is logged5.
